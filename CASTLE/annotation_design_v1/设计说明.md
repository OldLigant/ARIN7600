CASTLE 第一人称动作与环境标注：提示词与输出结构 v1 草案

本设计参考 `D:/QLD/ARIN7600/AriaRealLife/captions/run_pipeline.py` 中的 `PROMPT_V9_NOGAZE`（559 行）、`REGION_ADDENDUM`（761 行附近）、`READ_PROMPT`（787 行附近）和 `SPEECH_PROMPT`（839 行）。只交付提示词、输入约定和输出示例；未改动原脚本、未实现新管线、未调用模型。提示词和默认描述语言沿用原管线的英语，说明文档用中文，语音和可读文字保留原语言。

核心建议是继续采用“自然语言密集描述＋少量结构化字段”。只加更多固定动作类别仍然会丢失对象、交互方式和结果；一开始就使用完整人物—对象—状态知识图谱，又会显著增加实例追踪及一致性负担。这里保留原来的 action、action_brief、objects、environment、text_visible、speech、details 等概念，补足人物归属、时间和证据约束。

**与原提示词的关系**

| 原设计 | CASTLE v1 建议 | 原因 |
|---|---|---|
| 第一人称描述 | wearer 的动作仍写 I；其他人用片内 person_1 等标识 | 避免把看到别人倒水写成我倒水 |
| 一个有意义动作一个 segment | 保留；明确允许动作、语音、其他人的事件在时间上重叠 | 多人场景不能被强行排成互斥单线 |
| 30 秒通常 5–12 段 | 去掉数量目标，按实际行为转折分段 | 不为了凑数拆动作，也不为了数量限制漏动作 |
| 极细动作和 UI 描述 | 同样重视物理操作的对象、工具、方向、位置、前后状态 | CASTLE 中做饭、摆桌、清洗、传递物体比软件 UI 更多 |
| action_brief 去掉场景和身体细节 | 删除冗余，但保留有区分作用的目的位置、来源、工具和结果 | “把杯子放进水槽”和“放在桌上”对 lifelogging 不等价 |
| 第一段完整环境、之后只记变化 | 独立 initial_environment；segment.environment 记录变化 | 第一条事件可能是语音或与另一个事件重叠，不能让它承担隐含的全局状态 |
| 忽略转头造成的变化 | 区分 world_changes 与 newly_observed | 新看到一盘菜值得记录，但不能断言它刚被放上桌 |
| I notice / I read 作为注意事件 | 没有眼动时只描述可见朝向／交互，不直接断言注意、理解和阅读 | 朝向不等于注视或认知活动 |
| 每句话在 action/action_brief/speech 中全文复制 | speech.text 原文存一次，action 写谁对谁说话 | 保留原文，同时避免重复文本淹没动作输出 |
| HKT 字符串时间 | 模型输出片内数值秒；日期和视频偏移由调用端提供 | CASTLE 时间不能沿用 Aria 的 HKT 和固定 1 fps 假设 |
| 脸部打码、变声、匿名替换 | 不预设这些处理；人物 ID 与已提供的身份映射分开 | 原脚本使用 masked 图像和 anonymized.wav；CASTLE 不是同样的输入条件 |
| 眼动版／无眼动版 | 从无眼动版出发 | CASTLE 阅读实验的辅助眼动不是每条主视频都带的 gaze overlay |
| 文本区域精读 | 改成可选细节复核：文字、手—物交互、状态变化 | 不能只放大屏幕而忽略刀具、杯子、阀门和物体放置 |

原管线的 `process_clip` 实际先独立处理音频，再把语音结果交给全帧 caption 阶段；因此新提示词必须知道此次调用究竟拿到了原始音频还是只有转录。不能在只提供图片时要求模型“听出”背景声音。原 `build_context_text_v9` 中“没有 transcript/OCR 就从帧推导 speech”的约定不应移植；VAD 的声音活动窗口也不等于逐字语音边界。

**动作粒度**

可以把上层活动作为可选的 activity，但实际标签以 action 为核心：

```text
activity: Preparing a drink
I pick up the white mug from the counter.
I place the mug beneath the coffee-machine spout.
I press the brew button.
I lift the mug after the liquid stops flowing.
```

这比 Making Coffee 更细，但不会把伸手、触碰杯柄、弯曲手指、抬手腕全部拆成单独事件。只有在视频确实显示独立阶段、对象改变或结果改变时才拆。连续搅拌、清洗、步行、打字只需一段；动作持续期间发生的语音或他人行为可以另列重叠段。

activity 不是 26 类枚举，不能因为看到杯子就补成“冲咖啡”。若无法判断上层活动，填 null。action 也允许采用更保守的“倾斜容器朝向杯子”，而不在看不到液体时断言“倒入咖啡”。

actions 中记录手—物交互的关键事实；details 保留支持动作理解的手别、工具、方式和状态结果。没有观察到的“拿起之前”“倒完之后”不要补齐。片段边界切断的动作通过边界字段表示，不在下一段凭空重新开始。

**输入约定**

主提示词见 `主标注提示词.md`。它和以下调用端上下文、原始媒体及辅助证据一起构成请求。模板占位符必须在调用前填入实际值；不适用的输入明确列为 absent。

```text
clip_id: <unique clip ID>
duration_sec: <actual clip duration, not frame count>
viewpoint: egocentric
source_video: <main/dayN/Stream/video/HH.mp4>
source_wearer_id: <dataset stream label, or unknown>
source_date: <YYYY-MM-DD>
source_hour: <0..23>
source_start_offset_sec: <clip start within the source hour>

visual_input: <native video | timestamped_frames | absent>
visual_source_id: <e.g. video_0>
frame_times_sec: <actual timestamps if frames are supplied>
audio_input: <raw_audio | audio_in_native_video | absent>
audio_source_id: <e.g. audio_0, or absent>
transcript_input: <absent | automatic_unverified | audio_checked>
transcript_source_id: <if present>
ocr_input: <absent | automatic_unverified | visually_checked>
ocr_source_id: <if present>
trusted_unavailable_visual_intervals: <provided intervals, or []>
trusted_identity_mapping: <provided mapping with evidence, or absent>

All media and auxiliary timestamps below have been mapped to this clip's
local seconds. When the mapping is unknown, mark that source as unaligned
and do not use it to time an event.
```

默认只输入当前视角，避免主标注一开始就混入其他机位的已知事实。将来做跨视角复核时，再明确加入独立 source_id。既有五秒活动标签不作为主标注阶段的事实输入，可以在标注后比较，降低粗标签对细粒度描述的引导。

日期、源视频路径、偏移、模型版本、请求设置和耗时属于调用端记录，不能让模型猜。这些信息最终可以包在 annotation 外层。模型返回本设计的 annotation JSON；本草案没有要求它重复生成全部文件元数据。

**输出约定**

完整、可解析的假设示例见 `输出示例_假设场景.json`。示例是为了说明格式编写的，不对应 CASTLE 的真实标注。假设输入是 20 秒视频 `video_0` 及其对齐音频 `audio_0`，具有足以支持示例所述时序、物体状态和说话人匹配的画质／音质；示例不要求为没有新事件的剩余时间补写动作。

| 顶层字段 | 类型 | 含义 |
|---|---|---|
| schema_version | string | 固定 castle-caption-v1 |
| scene_summary | string | 当前片段一两句总述；只总结已支持的事实 |
| actors | array | 本片段人物；wearer、person_1 等；不做跨片段身份断言 |
| initial_environment | object 或 null | 第一处可用视觉证据的时间和详细环境描述；画面始终不可用则 null |
| visual_unavailable_intervals | array | 测试图或无法提供有用视觉信息的区间；不等于音频不可用 |
| segments | array | 可重叠的动作、语音、观察、环境事件 |
| activity_chain | array of string | 按发生顺序引用 wearer 动作段 ID；不是重复生成的概括字符串 |

actors 每项为 `{actor_id, description}`。wearer 固定为相机佩戴者，即使脸不可见也可以保留。person_N 只在当前 clip 内追踪，description 用衣物、可见位置等短描述。看不到的说话人可编号 speaker_1，但没有可靠视听对应时不与 person_1 合并。unknown 是保留标识，表示不能判定主体；多人共同动作可用多个 actor_ids。source_wearer_id 说明佩戴者是谁，并不告诉模型画面中哪张脸对应其他姓名。

initial_environment 为 `{time_sec, description}`。description 保留原提示词的丰富度：空间结构、照明、可辨认物品及状态／相对位置、其他人、可读屏幕／纸张内容；有实际音频证据时可加入此刻背景声音。不能把后半段才看到的东西塞进初始环境。摄像头观察不到的地方不属于“完整”描述范围。

每个 segment 的字段如下；空列表表示未观察到对应项目，null 表示不适用或无法确认，不能用空值表示观察到该对象不存在。

| 字段 | 类型／取值 | 约束 |
|---|---|---|
| segment_id | string | 本 clip 唯一，如 s001；后续修订按 ID 匹配 |
| start_sec / end_sec | number | 片内秒，`0 <= start < end <= duration`；按 `[start,end)` 理解 |
| event_type | action / speech / observation / environment | 仅结构分类，action 类别不限于枚举 |
| actor_ids | string[] | 引用 actors 或保留值 unknown；纯环境事件可为空 |
| activity | string 或 null | 可选上层活动，不能代替具体动作 |
| action | string | 完整动作／事件描述；wearer 用 I，他人用 ID |
| action_brief | string | 一项主要动作的压缩描述，保留区分所需对象、目标和结果 |
| objects | string[] | 参与此事件的具体对象；使用稳定、可区分的称呼 |
| environment | object | `{world_changes: string[], newly_observed: string[]}` |
| text_visible | string[] | 此时可读且有信息量的原文；不从常识补全 |
| speech | object 或 null | 语音段存说话人、来源、原文和核验状态；其他段为 null |
| details | string 或 null | 有用的手别、工具、方式、交互角色、可见结果或限制 |
| evidence | array | 当前段的证据来源、局部时间范围、支持事实和直接／间接性 |
| boundary | object | 见下文；避免把模型估计当精确动作时间 |
| uncertainties | string[] | 仅列对理解或使用有影响的具体不确定项 |

environment 两类含义不同：world_changes 是观察到实际变化，例如杯子从手里放到桌上；newly_observed 是视角变化后新获得的信息，例如转头后看见已经坐着的人。物体离开画面不能写成物体离开房间。若有显著地点切换，把新地点的详细可见状态写入 newly_observed，并在事件中写明有证据的移动；可以重新建立环境描述，不能永远累积上一房间的状态。

同一个变化只在最直接的事件段中描述一次。因为 segments 可重叠，environment 的时间依赖应按证据时间理解，不能按“数组上一项结束后”解释。没有变化时两个列表都为空。

speech 的结构为 `{speaker_id, source, text, verification}`。source 为 in_person、media 或 unknown；verification 为 audio_checked 或 transcript_only。原文保留语言切换、听清的重复和停顿词，听不清的局部用 `[unclear]`；无法恢复整句时 text 可为 null，并在 action 中说明可听见但无法辨清的说话。只拿到未核验转录时，可保留有时间依据的候选 speech 段，但必须标 transcript_only 和不确定性；明显填充段幻觉／重复噪声不应照抄。不能从图像单独生成台词。

evidence 每项为 `{source_id, modality, start_sec, end_sec, support, note}`。modality 为 visual、audio、transcript、ocr；support 为 direct 或 indirect。note 只写简短可复查事实，如“连续帧显示水从壶口进入杯中”，不要输出推理过程。对 transcript 的直接读取不等于验证台词真实说出，speech.verification 仍需标 transcript_only。混合证据时分别说明支持了哪个事实。此字段不提供貌似经过校准的百分比置信度。

boundary 为 `{start: observed|ongoing|uncertain, end: observed|ongoing|uncertain, precision: video_estimate|sampled_frames|audio_estimate|transcript_only}`。ongoing 表示事件被 clip 边缘截断；uncertain 表示因遮挡、采样或其他证据限制无法定位。precision 是本段时间边界的主要依据，不等于实际误差保证。稀疏帧下不要编造帧间微动作或毫秒级边界。

**可选复核提示词**

同目录的 `细节复核提示词.md` 延续原来的第二遍，但目标从“文字密集区域”扩展到“影响动作判断的细节”。它接受完整第一遍 JSON、带来源和时间的裁剪／短视频／音频，按 segment_id 返回 replacement，允许纠正 action、action_brief、objects、environment 等相互依赖字段。

单张裁剪不能证明运动过程，纯视觉裁剪不能纠正语音原文。裁剪复核不改变时间边界／事件数；确实需要重新分段时仅给 resegmentation_requests，留给拿到完整时序上下文的阶段处理。主标注失败或没有可用细节输入时，不强制第二次调用。

本阶段不规定 crop 坐标格式、模型名、帧率、分块长度或多遍调用次序；这些属于后续实现与实验。主输出不加入 bbox，避免为了尚未确定的采样方式绑定额外负担。

**小样本验证时重点看什么**

后续实际调用应至少检查：同一连续动作是否重复切碎、别人动作是否误归 wearer、真实变化与新入视野是否混淆、不可读文字是否被补写、对话提及的事情是否被标成发生、测试图和音频是否分别处理、简写是否丢失关键去向、粗标签是否影响细动作描述。当前示例只经过结构及一致性检查，提示词尚未用真实片段测试，不声称已达到某种准确率。
